## Пока нет домена и HTTPS

- Лендинг: HTTP по IP, noindex. NEXT_PUBLIC_SITE_URL остаётся пустым при сборке и запуске.
- Nginx не публикует `/admin` и `/api/admin`. Временный доступ к админке через зашифрованный SSH-туннель:

```sh
ssh -N -L 8080:127.0.0.1:3000 root@95.85.251.199
```

После подключения открыть http://127.0.0.1:8080/admin. Серверный APP_ORIGIN для этого временного режима: http://127.0.0.1:8080. Пароль админки передаётся внутри SSH-туннеля. VPS root-пароль и пароль приложения — разные учётные данные.

- LEADS_ENABLED=false, POLICY_READY=false: публичные заявки пока не принимаются. Не загружать рабочую локальную SQLite на иностранный VPS. Отдельно подтвердить допустимость размещения персональных данных и обновить политику под фактический хостинг до включения формы.

## Раскладка на сервере

- `/opt/mk-landing/releases/<release>` — код и production-сборка под Linux; `current` указывает на активный релиз.
- `/etc/mk-landing.env` — отдельная конфигурация сервера с хешем пароля, root:mk-landing, права 640. Не копировать локальный .env.local целиком.
- `/var/lib/mk-landing/landing.sqlite` — новая отдельная БД, права каталога 700, владелец mk-landing.
- Процесс запускается пользователем mk-landing через systemd, порт 3000 слушает только loopback.
- Для Image Optimization требуется существующий доступный на запись `.next/cache` активного релиза. Остальные файлы приложения доступны процессу только на чтение.
- Node.js 24+, Nginx, запуск systemctl enable --now mk-landing. Сначала проверять nginx -t и только затем reload. Не заменять конфигурации других сайтов без проверки.

Никогда не включать в архив публикации `.env.local`, `data/`, `.git/`, Windows `node_modules/`, локальную `.next/`, исходные Photos/design/References и QA-артефакты. В релиз передавать код, public, manifest/lockfile и необходимые build-конфигурации. Зависимости устанавливать под Linux через npm ci. Сборка на VPS с 2 GB требует контроля памяти и может потребовать временного swap; Windows-сборку не переносить как Linux-релиз.

Перед переключением релиза проверить сборку, локальный HTTP 200, создание новой БД, права, status службы, отсутствие публикации порта 3000 и доступ по IP через Nginx. При неудаче вернуть ссылку current на предыдущий релиз и перезапустить службу.

После выбора домена заменить временную схему: HTTPS, основной APP_ORIGIN, доступ к админке по HTTPS, SEO_DEPLOY.md и отдельная проверка условий включения формы. INFRA_READY пока false.
