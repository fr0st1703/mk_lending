# SEO перед публикацией

Домен пока не выбран. В локальной сборке индексация намеренно выключена через meta robots `noindex, nofollow`; sitemap пустой. `robots.txt` разрешает загрузку HTML, чтобы поисковик мог увидеть noindex, и запрещает обход `/api/`. Это не ограничение доступа: админка защищается авторизацией.

## Что уже подготовлено

- Серверный HTML, язык `ru`, один H1, разделы H2, услуги H3, описательные title/description.
- Canonical только главной страницы и отдельный canonical политики при заданном домене. Страницы админки и согласия не наследуют canonical главной.
- Open Graph и Twitter large image, PNG 1200 × 630 по `/opengraph-image`, favicon.
- JSON-LD: Person, четыре Service; после настройки домена — связанные WebSite и WebPage. Без вымышленных адресов, цен, рейтингов и отзывов.
- `/admin`, `/privacy`, `/consent` имеют noindex. Админка и API дополнительно получают X-Robots-Tag. Несуществующие URL возвращают 404.
- Локальные шрифты, оптимизированные WebP, размеры портретов заданы, главный портрет предзагружается, второстепенные иллюстрации загружаются при приближении к экрану.

## Когда появится домен

1. Выбрать основной HTTPS-адрес с www или без www. В существующем `.env.local` заполнить `NEXT_PUBLIC_SITE_URL=https://ваш-домен` и `APP_ORIGIN=https://ваш-домен`. Не перезаписывать файл целиком: там хеш пароля и настройки базы. Адрес должен быть без пути, параметров и авторизации. Не задавать публичный URL для временной версии, которую не нужно индексировать.
2. На reverse proxy настроить HTTPS и постоянный редирект HTTP → HTTPS, а также второго варианта домена → основного. Не перенаправлять произвольные несуществующие пути на главную.
3. Выполнить `npm run build`, затем перезапустить приложение. Публичный адрес встраивается при сборке. Установка переменной только после сборки недостаточна.
4. На реальном домене проверить HTTP 200, единственный canonical, `index, follow` главной, абсолютные og:url / og:image / twitter:image без localhost, PNG превью. Убедиться, что robots.txt доступен и содержит ссылку на sitemap.xml; в sitemap — только главная с основным HTTPS-адресом.
5. Проверить `/admin`, `/privacy`, `/consent`: noindex; неизвестный путь: 404. Служебные страницы в sitemap не добавлять.
6. Добавить сайт в Google Search Console и Яндекс Вебмастер, подтвердить владение, отправить `/sitemap.xml`. Проверить главную инструментом проверки URL и структурированные данные через Schema Markup Validator. Превью проверить реальной ссылкой в Telegram.
7. После публикации проверить мобильную страницу и Core Web Vitals. Оценка на локальном компьютере не заменяет данные реальных посетителей. Индексация и позиции не гарантируются техническими настройками.

Проверки SEO: `npm run test:e2e -- tests/seo.spec.ts`. По умолчанию тест ожидает локальную сборку без домена; для публичной сборки передать `SEO_EXPECT_SITE_URL`, совпадающий с адресом, использованным при build. Тестовый сервер использует отдельную SQLite на порту 3100 и не работает с рабочими заявками.

Готовность backend, реквизитов и обработки заявок проверяется отдельно по [BACKEND_OPERATIONS.md](BACKEND_OPERATIONS.md). SEO-настройка не включает публичный приём заявок автоматически.

Источники: [Google: noindex и доступность для обхода](https://developers.google.com/search/docs/crawling-indexing/block-indexing), [Google: sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap), [Next.js: метаданные](https://nextjs.org/docs/app/api-reference/functions/generate-metadata).
